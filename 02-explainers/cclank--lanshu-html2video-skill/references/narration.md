# 口播模式：写给人念的稿子

口播模式不是"音乐版再附一个文档"。它是**另一种剪法**，因为承载内容的东西换了：
音乐版里屏幕文字就是内容，口播版里声音才是内容，文字退回去当锚点。

三件事随之改变：

| | 音乐版 | 口播版 |
|---|---|---|
| 时长由什么决定 | 默读速度（可读性下限） | **语速**（旁白长度） |
| 屏幕文字 | 完整承载信息 | **只留标题和数字**，图注多半要删 |
| `target.seconds` | 求解目标 | **只是断言**，记录实际长度 |

启用方式：`audio.mode: "voice"`，并给**每一个**场景写 `narration`。schema 会强制后者。
然后：

```bash
node scripts/render.mjs --storyboard ./work/myrun --script    # 只出稿
node scripts/render.mjs --storyboard ./work/myrun             # 出稿 + 渲染
```

稿子落在 `narration.md`。voice 模式下渲染会自动出稿，因为不给稿子的口播成片是没法录的。

## 最重要的一条：不要把屏幕上的字念出来

这是口播视频最常见、也最致命的毛病。观众正在读标题，你同时把同一句话念出来，
两个通道传的是同一份信息 —— 结果是两边都记不住，而且显得敷衍。

屏幕负责**说是什么**，旁白负责**说为什么、所以呢、哪来的**。

| 画面标题 | ❌ 复述 | ✅ 补充画面没说的 |
|---|---|---|
| 把思维翻译成人话 | "这个方法能把思维翻译成人话。" | "Anthropic 最近公开了一个方法，冲的是可解释性里一个很基本的麻烦。" |
| 一个负责说，一个负责猜 | "一个模型负责说，一个负责猜。" | "方法本身不复杂，难的是怎么知道翻译得对不对。他们的办法是训两个模型……" |
| NLA 也会编造 | "NLA 也是会编造的。" | "但这套方法有个必须说清楚的毛病。" |

生成的稿子里每一场都有「画面」一栏，写着那一刻屏幕上有什么。它在那里是**为了让你避开它**。

## 屏幕文字要收

旁白讲得完的东西，不必再写在画面上。实践下来：

- `figure` 场景的 `caption` 通常整条删掉 —— 那句话交给旁白说
- `sub` 保留一到两行，别三行
- `stat` 的大数字和 `of` 留着（数字看比听准）
- `ladder` 的条目留着，但旁白要把它们**串起来**讲，不是逐条念

校验器会替你抓这个：如果某一场屏幕文字的默读时间超过旁白时长，它会报

```
scene "s7": its on-screen text needs 3.0s longer to read than the narration lasts.
```

意思是这一场你在要求观众同时读和听。两个解法：把文字砍掉，或者把旁白写长
（如果画面上的内容确实值得那么多时间）。两条都对，取决于那些字该不该留。

## 口语句法，不是书面语

念出来和读进去是两种语言。稿子要按念的写：

- **短句**。一个逗号一个呼吸。书面语那种层层嵌套的定语，念出来会断气。
- **不要"其"、"之"、"该"、"上述"**。念着别扭。
- **数字口语化**。写 "26%" 屏幕上没问题，念的时候是"四分之一左右"更顺 ——
  除非精确值本身是重点。
- **专有名词保留原文**。NLA、SWE-bench、Opus 4.6 照写，念的人自然会处理。
- **用 `\n` 断句**。稿子会把它保留成换气点，也是画面重排的依据。

沿用 [editorial.md](editorial.md) 的禁用词表：深入探讨、让我们看看、带你了解、
一探究竟、惊艳、革命性、总而言之。念出来比写出来更假。

## 时长是怎么算的

没有音频可量，所以从文字估。估的是**音节**不是字符，这个区别很关键 ——
中文语速按音节稳定，而字符到音节的映射对这个管线偏爱的素材恰好不是 1:1：

```
"26%"        3 字符  →  百分之二十六        6 音节
"1 Tbps"     6 字符  →  一 T-b-p-s ≈        4-5 音节
"SWE-bench"  9 字符  →  ≈                   5 音节
```

按字符数估会把数据密集的稿子**严重估短**，每个数字镜头都会被切掉尾巴。所以
`lib/speech.ts` 做了展开：数字串 n 位算 `n + n/2` 音节，`%` 算 3，拉丁串算长度一半。

默认 **4.3 音节/秒**（约 258 字/分钟），是常规解说的语速。误差约 ±15%，由每场的
尾留吸收。你的语速明显不同就换：

```bash
node scripts/render.mjs --storyboard ./work/myrun --script --sps 3.8   # 慢一点
```

画面会跟着重排，稿子里的语速假设也会更新。

## 稿子里有什么

`narration.md` 分三部分：

1. **头部** —— 成片时长、总字数、语速假设、录制须知
2. **逐场** —— 时间码（互不重叠的连续窗口，可分段重录）、那一刻的画面、
   时长预算（旁白 + 余量）、要念的那句话
3. **连读版** —— 去掉一切标注的纯旁白，给提词器用

余量低于 0.2s 的场景会单独标出来，那意味着念的时候不能停顿 —— 通常该砍几个字。

## 已知边界

- **稿子不含音频。** 你自己录，或者外接 TTS 后用 `voiceDurations` 把实测时长喂回
  `resolveTimeline`（函数签名已经留好，接线还没做）。
- **没有烧字幕。** 字幕需要词级时间戳，那要么来自 TTS，要么要跑强制对齐 —— 属 P1。
- **时长是估的。** 实际录音会和排布差几秒。每场的尾留是为此留的缓冲，但如果你
  的语速和 4.3 音节/秒差得远，先用 `--sps` 校准一次再录。
