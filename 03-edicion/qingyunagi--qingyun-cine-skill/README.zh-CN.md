# Qingyun Cinematic Video Editor

[English](README.md) | [简体中文](README.zh-CN.md)

`qingyun-cine-skill` 是一个面向 Codex 的通用影视剪辑 skill，用来处理电影预告片、片花、混剪、短视频、音乐卡点、宣传片、角色高光、游戏剪辑、动作剪辑、国风/仙侠类视频重剪等任务。

它的核心原则是：**先出剪辑蓝图，用户确认后再渲染成片**。

也就是说，当用户说「帮我剪一个预告片」「优化这个混剪」「做个短视频」「剪得燃一点」时，Codex 不会一上来就直接导出视频，而是先分析素材、设计节奏、规划镜头、安排声音和字幕，生成一套可审阅的剪辑方案。用户确认后，才进入最终渲染。

## 适合做什么

这个 skill 适合以下类型的视频工作：

- 电影级预告片
- 影视片花
- 快节奏混剪
- 音乐卡点视频
- 宣传片
- 短视频重剪
- 角色高光
- 游戏高燃剪辑
- 动作/打斗剪辑
- 国风、仙侠、奇幻类视频
- 带对白、音效、片名卡的叙事向剪辑

它尤其适合需要「不只是展示素材，而是制造情绪和悬念」的剪辑任务。

## 核心特性

### 1. 默认 PLAN-FIRST，两阶段工作流

skill 默认采用两阶段流程：

**第一阶段：只出剪辑蓝图**

- 分析素材信息
- 检测镜头和场景
- 生成镜头清单
- 生成 contact sheet 预览图
- 设计故事结构和节奏
- 安排对白、音乐、音效、字幕、片名卡
- 生成 `beat_sheet.md`
- 生成 `edit_plan.json`
- 不渲染最终成片

**第二阶段：用户确认后再渲染**

- 按确认后的 `edit_plan.json` 剪辑
- 混合原声对白、BGM 和音效
- 导出最终视频
- 生成质量检查报告

这样可以避免「还没看方案就先渲染」的问题，也能减少反复导出造成的时间浪费。

### 2. 按预告片逻辑组织内容

这个 skill 不鼓励按素材时间线顺序简单拼接，而是会把视频当成一个真正的短片或预告片来设计：

- 开头钩子
- 世界观或场景建立
- 悬念出现
- 冲突升级
- 动作或情绪高潮
- 片名、Logo 或结尾记忆点

例如一个 30 秒预告片，可能会被设计成：

- 0-3 秒：强钩子，先抓住观众
- 3-8 秒：建立人物、场景或事件
- 8-15 秒：保留关键对白或悬念信息
- 15-25 秒：动作升级，节奏加快
- 25-30 秒：最大奇观、片名落点、声音余味

### 3. 素材分析更清楚

第一阶段可以生成素材分析文件，帮助用户知道哪些镜头值得用、哪些镜头应该缩短或避开。

常见输出包括：

- `source_info.json` 或 `media_inventory.md`
- `shot_manifest.csv`
- `contact_sheet.jpg`

`shot_manifest.csv` 可以记录：

- 镜头开始时间
- 镜头结束时间
- 镜头时长
- 画面描述
- 能量评分
- 叙事功能
- 是否含对白
- 推荐用法

这能让剪辑从「凭感觉挑素材」变成「有依据地编排镜头」。

### 4. 支持音乐卡点和强节奏混剪

如果用户提供 BGM，skill 可以围绕音乐结构做节奏规划：

- 鼓点位置
- drop 点
- break 段
- 重击点
- 对白留白位置
- 音乐压低位置
- whoosh、hit、riser、sub drop 等音效位置

这对高燃混剪、预告片、游戏剪辑和动作剪辑很重要。它会让镜头切点跟声音发生关系，而不是随机快切。

### 5. 对白、字幕和片名卡都有规划

如果素材里有原声对白，skill 会考虑：

- 哪些对白真正有信息量
- 对白总时长是否过长
- 对白出现时 BGM 是否需要压低
- 是否需要中文字幕
- 字幕是否挡脸
- 文案卡是否过多
- 片名卡出现的时机和停留时长

如果用户明确说不要字幕，skill 会遵守；如果用户需要字幕，则会把字幕作为剪辑方案的一部分，而不是临时补上。

### 6. 带质量检查意识

渲染后，skill 会要求输出或更新 `qc_report.txt`，检查内容包括：

- 成片时长是否符合要求
- 分辨率和帧率是否正确
- 是否有黑帧、错帧或明显卡顿
- 是否重复使用镜头过多
- 是否有静态镜头停留过久
- 对白是否清楚
- 音乐是否盖住对白
- 片名卡是否足够有记忆点
- 字幕是否可读
- 整体是否像正式预告片，而不是素材堆叠

## 操作步骤

### 第一步：安装 skill

把仓库克隆到 Codex 的 skills 目录：

```bash
git clone https://github.com/qingyunAGI/qingyun-cine-skill.git ~/.codex/skills/qingyun-cine-skill
```

如果你的 Codex 环境需要重新加载 skill，请重启 Codex 或刷新 skill 列表。

### 第二步：提出剪辑需求

你可以直接用自然语言描述目标，例如：

```text
帮我把这些素材剪成一个 35 秒电影级动作预告片，节奏要快，保留少量对白，结尾有片名卡。
```

也可以说得更具体：

```text
做一个 30 秒以内的国风高燃混剪，开头 3 秒必须抓人，15 秒进入动作升级，最后落片名。
```

建议提供的信息包括：

- 源视频路径
- 背景音乐路径或音乐风格
- 目标时长
- 横版或竖版
- 发布平台
- 是否要字幕
- 是否保留原声对白
- 想要的风格参考
- 必须使用或必须避开的镜头

如果信息不完整，skill 会采用合理默认值，并把假设写入 `intake_summary.md`。

### 第三步：先审看剪辑蓝图

第一阶段结束后，通常会得到这些文件：

| 文件 | 用途 |
| --- | --- |
| `intake_summary.md` | 记录需求、默认值、假设和缺失信息。 |
| `media_inventory.md` / `source_info.json` | 记录素材时长、分辨率、帧率、音频、编码和质量情况。 |
| `shot_manifest.csv` | 镜头清单，用来判断每个片段的价值和用途。 |
| `contact_sheet.jpg` | 素材画面总览，方便快速审看。 |
| `beat_sheet.md` | 人类可读的节奏和叙事结构方案。 |
| `edit_plan.json` | 可执行的剪辑时间线计划。 |
| `qc_plan.md` 或初版 `qc_report.txt` | 质量检查计划。 |

注意：这个阶段还不会生成最终视频。

### 第四步：确认或要求修改

如果方案可以执行，可以回复：

```text
按这个方案剪
```

```text
开始渲染
```

```text
可以出成片
```

如果还想调整，可以直接指出问题：

```text
开头再狠一点，减少对白，把高潮提前到 25 秒。
```

```text
动作段太散了，按追逐、交手、爆点的顺序重新排。
```

### 第五步：渲染成片并做 QC

用户明确确认后，skill 才会进入第二阶段：

- 按 `edit_plan.json` 剪辑
- 混合 BGM、对白和音效
- 控制对白和音乐的响度关系
- 导出最终视频
- 生成最终 `qc_report.txt`

## 为什么它有优势

### 更容易对齐创意方向

传统剪辑任务经常会出现一个问题：视频已经渲染完了，但用户发现故事结构、节奏或气质不是自己想要的。这个 skill 先出蓝图，让用户在渲染前就能看到剪辑意图，减少返工。

### 更像真正的预告片

它会主动思考钩子、悬念、冲突、升级、高潮和片名落点，而不是把好看的镜头简单串起来。对于影视预告、宣传片和高光剪辑，这一点非常关键。

### 修改成本更低

有了 `beat_sheet.md` 和 `edit_plan.json`，后续修改可以精确到时间段和镜头，例如：

- 把 0-3 秒钩子换得更强
- 把 15-25 秒动作段加快
- 删除某句对白
- 把片名卡提前
- 减少重复法阵镜头

这比重新从头剪一版更高效。

### 更适合复杂素材

当素材很多、音乐很强、对白需要保留、还要加片名和音效时，直接剪很容易乱。这个 skill 会先把素材、节奏、声音和文字拆开规划，再合成一个清楚的时间线。

### 更安全，适合上传公开仓库

skill 内置了隐私和 Git 安全规则，提醒不要把以下内容提交到公开仓库：

- 原始视频
- 渲染成片
- 音频素材
- 抽帧图片
- contact sheet
- 本机绝对路径
- 用户名
- 项目目录
- API key
- GitHub token
- Cookie 或其他凭据

示例会使用 `<SOURCE_VIDEO>`、`sources/source_a.mp4` 这类占位符，避免泄露真实项目细节。
